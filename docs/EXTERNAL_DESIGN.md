# 外部設計書（External Design Document）

## 1. システム概要

### 1.1 プロダクト名

**Shinya Ishizaki's Official Website**

### 1.2 目的

Shinya Ishizakiの公式ウェブサイトとして、以下の情報を発信する：

* プロフィール・自己紹介

* 技術スキルの紹介

* Tech Blogの最新記事の紹介

* メンタリングサービス（MENTA）の案内

* 問い合わせフォームを通じた依頼・相談の受け付け

本プロジェクトでは、問い合わせフォームの導入により、訪問者がサイト内から直接連絡先を送信できるようにし、スパム対策と運用しやすさを両立することを目的とする。

### 1.3 対象ユーザー

* Shinya Ishizakiの情報を知りたい者

* 技術ブログの読者

* メンタリングサービスに興味のある者

* ポートフォリオを参照する採用担当者

### 2.2 外部システムとの連携

#### 2.2.1 Tech Blog (RSS連携)

* **URL**: `https://tech-blog.shinyaishizaki.com/`

* **連携方式**: RSS フィード取得

* **フィードURL**: `https://tech-blog.shinyaishizaki.com/feed.xml`

* **取得頻度**:

  * 手動: `ruby scripts/fetch_latest_posts.rb` で実行時に取得

  * 自動: GitHub Actions の定期実行（スケジュール実行）

* **表示件数**: 最新5件

* **連携内容**:

  * 記事タイトル

  * 記事URL

  * 公開日時

#### 2.2.2 問い合わせフォーム

* **フォームURL**: `/contact/`
* **連携方式**:

  * フロントエンド: Jekyll / HTMLフォーム
  * ボット対策: Cloudflare Turnstile
  * サーバーレス処理: Cloudflare Workers
  * メール送信: Resend または同等の送信API
* **機能**:

  * お名前入力
  * メールアドレス入力
  * 問い合わせ種別（General / Mentoring / Other など）
  * メッセージ本文入力
  * Turnstile による検証
  * 送信後の成功メッセージ表示
  * 送信失敗時のエラー表示

* **設計方針**:

  * フォーム送信はサイト内の `/contact/` から行う
  * サイト自体はフォーム表示のみを担当し、メール送信ロジックは外部サービスへ委託する
  * 送信したデータはサイトのDBに保持しない
  * 送信処理の実行にはCSRFやスパム対策を含めたセキュリティ設計を適用する

## 3. ユーザーシナリオ

### 3.1 シナリオ1: 初訪問ユーザー

1. トップページ (`/`) にアクセス
2. "Hello, I'm Shinya Ishizaki" のメッセージを確認
3. 5つのコアスキルを確認
4. 最新Tech Blogブログ記事を確認
5. Tech Blogへのリンクをクリック、またはAboutページへ移動

### 3.2 シナリオ2: 詳細情報を求めるユーザー

1. Aboutページ (`/about/`) にアクセス
2. 詳細プロフィールと経歴を確認
3. メンタリングリンクをクリック

### 3.3 シナリオ3: メンタリングに興味あるユーザー

1. トップページまたはAboutページからメンタリングセクションに移動
2. メンタリングページ (`/mentoring/`) にアクセス
3. サービス内容とプランを確認
4. MENTAへのリンク（紹介リンク）をクリック
5. MENTA上でメンタリング申込

### 3.4 シナリオ4: 問い合わせを送信したいユーザー

1. ユーザーがサイトのヘッダーまたはフッターから `/contact/` にアクセス
2. 氏名、メールアドレス、内容を入力
3. Turnstile の検証が完了したことを確認
4. 「送信」ボタンを押下
5. Cloudflare Worker が入力内容を検証し、Resend 経由でメール送信
6. フォームは送信成功メッセージを表示し、ユーザーは完了を確認
7. 送信失敗時は、再入力を促すエラーメッセージを表示

## 6. 依存関係・制約事項

### 6.1 外部依存関係

* Tech Blog (`https://tech-blog.shinyaishizaki.com/`)のRSSフィードが利用可能であること
* MENTA (`https://menta.work/`) のサービスが継続していること
* インターネット接続の可用性
* 問い合わせフォーム送信先のメールAPIサービスが運用可能であること

### 6.2 制約事項

* デプロイには GitHub Pages の設定が必要
* ローカル開発には Ruby と Bundler のインストールが必須
* RSS取得には20秒以内のタイムアウト設定
* 問い合わせフォームの受信処理は静的サイトの制約上、外部サーバーレス処理に依存する
* API キーや送信先メールアドレスは公開リポジトリに含めない

### 6.3 GitHub Projects による進行管理

* 実装作業は GitHub Projects の `Contact Form` カードまたは関連Issueで管理する
* 各タスクは完了条件を明確化する
* 変更が大きくなった場合は、設計書と実装を同期して更新する

### 6.4 運用制約

* 本サイトは静的サイトであるため、問い合わせフォームの受信処理はサーバーレスの外部サービスに依存する
* 送信先メールアドレスや API キーは秘密管理し、公開リポジトリに直書きしない
* 送信内容は必要最小限に抑え、返信は現状の運用量に応じてメールまたは別手段で対応する

## 7. 受け入れ基準

* `/contact/` ページが公開され、フォームが表示される
* Turnstile によりボット送信が防止される
* 正常な問い合わせ内容がメール送信される
* 送信失敗時に再試行の案内が表示される
* 送信内容が「必要最低限」のみで外部サービスへ渡される
* GitHub Projects の実装タスクと整合している

## 8. 追加メモ

本設計は Jekyll ベースの静的サイトに対し、問い合わせフォームはサイト内フォーム + 外部送信処理の構成を採用する。これにより、GitHub Pages の制約を回避しつつ、簡潔な運用と安全性を両立する。
